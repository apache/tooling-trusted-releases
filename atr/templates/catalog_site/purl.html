Package URLs for ASF releases

Every release in this catalog carries a Package URL (PURL) - a short, portable identifier for a piece of software that doesn't depend on any one package manager. You've landed here because you followed the bare PURL prefix; the sections below explain the shape and how to resolve one.

The shape

An ASF release PURL looks like this:

pkg:software-id/apache.org/the+asf/<project>@<version>

The type is software-id and the namespace is apache.org/the+asf - the prefix you're on now. What follows is the project's own key and the release version, for example pkg:software-id/apache.org/the+asf/tomcat@10.1.0.

Resolving one

The namespace doubles as a resolvable address. Swapping the pkg:software-id/ prefix for https:// gives a link that redirects into this catalog:

https://apache.org/the+asf/tomcat@10.1.0

A bare PURL like that resolves to the release's manifest - a JSON document listing its artifacts, along with the signatures, checksums and any SBOMs. To browse the same releases as web pages, follow the catalog link below.

Jumping straight to a file

Add a query string and the same URL resolves to a single download rather than the manifest. A release exposes these qualifiers:

  • class - src, bin or docs
  • os and arch - for platform-specific binaries
  • ext - the file extension, such as tar.gz
  • file_name - the exact file name, which always addresses one file
  • subpath - the distinguishing tail of a file name, where it's unique

So the source archive of the release above is:

https://apache.org/the+asf/tomcat@10.1.0?class=src&ext=tar.gz
